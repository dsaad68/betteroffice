## Reference vs candidate

The slide is "Interpret and understand gateway traffic in real time," showing a two-line title, an "Events" arrow feeding a five-row alert table (Salesforce/Box entries), a white rounded-rectangle box with a refresh/sync icon, four orange numbered callout boxes, and an off-slide dark-red editor's note bleeding in from the left edge. LibreOffice shows the full two-line title, a two-curved-arrow refresh icon inside the white box, white text on the red editor's note and correct page footer "13". BetterOffice cuts the title's second line off partway down, renders the white box with no icon at all, shows the editor's-note text in dark gray instead of white, wraps that same note text across one fewer line, and shows the raw field placeholder "‹#›" instead of "13" in the footer. The table rows, arrow, callout box fills/positions, and numbered circles otherwise match closely.

## Findings

### 1. Title's second line is hard-clipped instead of overflowing

- Where: Title 1 (id 2), "Interpret and understand gateway traffic in real time," region x 0.034-0.96, y 0.066-0.209.
- Reference: both lines render in full — "Interpret and understand gateway traffic in / real time" — extending visibly below the placeholder's nominal box bottom, uncropped.
- Candidate: the first line sits lower than in the reference and the second line ("real time") is cut off roughly through the middle of the letters, as if clipped at a hard horizontal boundary.
- XML: the slide's title placeholder carries no local `spPr`/`bodyPr` override (`<p:spPr/><a:bodyPr/><a:lstStyle/>`), so it inherits box size from the layout and text formatting from the master:
  ```
  layout: <a:xfrm><a:off x="310855" y="341313"/><a:ext cx="8469608" cy="731837"/></a:xfrm>
  master bodyPr: <a:bodyPr vert="horz" wrap="square" ... anchor="ctr" ...><a:prstTxWarp prst="textNoShape"/></a:bodyPr>
  master titleStyle: <a:lnSpc><a:spcPct val="80000"/></a:lnSpc> ... <a:defRPr sz="3200" .../>
  ```
  No `a:normAutofit` or `a:noAutofit` is present anywhere in this chain.
- Why the candidate is wrong: the box is 731837 EMU (0.8in / ~76.8px) tall, but two lines of 32pt text at 80% line spacing need roughly 82px — more than the box height even before insets. With no autofit element specified, a conformant renderer must let the text overflow the box visibly (as the reference does) rather than clip it; BetterOffice is instead clipping the overflow at the shape's bounding box.

### 2. Refresh/sync icon is entirely missing

- Where: Freeform 39 (id 104) and Freeform 40 (id 105), grouped under Group 102 (id 103), inside the white rounded-rectangle box (Rounded Rectangle 26, id 27), region x 0.272-0.33, y 0.466-0.568.
- Reference: a dark two-curved-arrow "refresh" icon is drawn inside the white box.
- Candidate: the white box is empty; no trace of the icon appears anywhere in the region.
- XML: both shapes are `custGeom` paths built from legacy guide formulas:
  ```
  <a:custGeom><a:avLst/>
    <a:gdLst>
      <a:gd name="T0" fmla="*/ 332 w 380"/>
      <a:gd name="T1" fmla="*/ 0 h 151"/>
      ...
    </a:gdLst>
    ...
  </a:custGeom><a:grpFill/>
  ```
- Why the candidate is wrong: the two `custGeom` shapes are present in the slide XML with valid guide lists and path data (and `<a:grpFill/>` inheriting the group's dark fill), matching what the reference draws. BetterOffice draws nothing at all for either shape, so at minimum the guide-formula (`gdLst`/`fmla`) resolution or the resulting path is failing silently rather than producing a wrong-but-visible shape.

### 3. Text with no explicit run color ignores the shape's fontRef scheme color

- Where: Rectangle 125 (id 126), the off-slide red banner "Please replace with new breadcrumb boxes from slide 23," region x -0.105 to 0.123, y 0.362-0.762.
- Reference: text is white, matching the shape style's `a:fontRef` scheme color.
- Candidate: the same text renders as a dark slate gray on the dark-red banner.
- XML: the shape carries
  ```
  <p:style>...<a:fontRef idx="minor"><a:schemeClr val="lt1"/></a:fontRef></p:style>
  <p:txBody>...<a:r><a:rPr lang="en-US" dirty="0"/><a:t>Please replace with new breadcrumb boxes from slide 23</a:t></a:r>...
  ```
  with no `a:solidFill` on the run. Compare Rounded Rectangle 76 ("Convert traffic data into human-readable events lists"), whose run does carry an explicit `<a:solidFill><a:schemeClr val="bg1"/></a:solidFill>` and renders correctly (white) in both engines.
- Why the candidate is wrong: a run with no direct color must inherit from the enclosing shape's `p:style/a:fontRef`, resolved through the theme/color map (here `lt1`, a light/white scheme color). BetterOffice is not applying that inheritance for this shape and falls back to a default dark gray instead.

### 4. Off-slide banner text wraps differently

- Where: Rectangle 125 (id 126), same shape and region as finding 3.
- Reference: wraps as "Please replace" / "with new" / "breadcrumb boxes" / "from slide 23" (4 lines).
- Candidate: wraps as "Please replace with" / "new breadcrumb boxes" / "from slide 23" (3 lines) — each line fits noticeably more text than the reference.
- XML: `<a:bodyPr rtlCol="0" anchor="ctr"/>` — no explicit wrap width override, default insets apply.
- Why the candidate is wrong: given the same fixed shape width (2087880 EMU) and default theme font/size, the two engines are measuring the same words to different widths, so BetterOffice under-wraps relative to the reference. This box is mostly off-slide (an editor's note), so the practical impact is limited to the small visible sliver, but the wrap divergence itself is a text-measurement mismatch.

### 5. Footer slide-number field not evaluated

- Where: master shape "Rectangle 7" (id 12), the `slidenum` footer field, bottom-right corner, region x 0.955-0.979, y 0.922-0.952.
- Reference: shows the actual page number, "13".
- Candidate: shows the literal cached field text, a "‹#›" glyph.
- XML: `<a:fld id="{4ABDCABE-3F10-B64C-92F1-862014417034}" type="slidenum">...<a:t>‹#›</a:t></a:fld>` — the `<a:t>` child of an `a:fld` is only a cached fallback value; a conformant renderer must substitute the live slide index.
- Why the candidate is wrong: the field type `slidenum` is unambiguous and the reference resolves it correctly; BetterOffice is displaying the unevaluated cached text instead of computing the slide's position in the deck.
