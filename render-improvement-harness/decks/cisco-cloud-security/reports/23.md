## Reference vs candidate

The slide is a row of colored panels ("Audit", "Panel C", "Panel A" + "Panel B", "Control & Analyze" + Securlet/Gateway logos, "Detect", "Product X", "Threat…") each with a bold heading and a small icon. The reference (LibreOffice) draws every heading upright in white (dark on the gray "Control & Analyze" panel), every panel box filled with its intended color, and every icon as a small cropped, recolored glyph. The candidate (BetterOffice) mirrors the heading text horizontally on five panels, drops the fill entirely on the "Audit" box and its Shadow-IT document icon, renders almost every heading in a generic dark gray instead of white, and shows the full uncropped source artwork (including baked-in title/subtitle text) behind several icons instead of the isolated icon glyph.

## Findings

### 1. Text mirrored on shapes with rot=180°+flipV

- Where: "Audit" (id 5), "Panel C" (id 7), "Panel A" (id 14), "Panel B" (id 15), "Control & Analyze" (id 30) — the four leftmost panel boxes plus the "Panel B" caption.
- Reference: text reads normally, upright, left-to-right ("Audit", "Panel C", "Panel A", "Panel B", "Control & Analyze").
- Candidate: each string is drawn with its character order reversed and every glyph flipped left-right, e.g. "Audit" renders as "tibuA", "Panel A" as a mirrored "Panel A".
- XML:
  ```
  <a:xfrm rot="10800000" flipV="1">
    <a:off x="1980832" y="717630"/><a:ext cx="1261872" cy="2170239"/>
  </a:xfrm>
  ```
- Why the candidate is wrong: composing a 180° rotation with a vertical flip cancels to a pure horizontal flip of the *geometry* with zero net rotation (Rotate(180°) ∘ FlipV = FlipH). PowerPoint/LibreOffice keep the text upright and unmirrored in this case — flipping a shape does not mirror the glyphs inside it. The candidate instead renders the shapes as if a literal horizontal mirror were applied to the text run itself.

### 2. `<a:grpFill/>` not resolved against the parent group's solid fill

- Where: "Audit" box (id 5), region `[0.021, 0.353, 0.159, 0.775]`; the document-icon outline built from "Freeform 12" + six small rectangles (ids 17-23) inside Group 15, region `[0.356, 0.583, 0.428, 0.663]`.
- Reference: the "Audit" box is filled cisco-green (`99CC31`); the document icon under "Panel B" is drawn white.
- Candidate: both are invisible — the "Audit" box shows the white slide background, and the document icon does not appear at all.
- XML:
  ```
  <p:grpSp><p:cNvPr id="4" name="Group 3"/>
    <p:grpSpPr>...<a:solidFill><a:srgbClr val="99CC31"/></a:solidFill></p:grpSpPr>
    <p:sp><p:cNvPr id="5" name="Rectangle 4"/>...<a:grpFill/>...
  ```
  ```
  <p:grpSp><p:cNvPr id="16" name="Group 15"/>
    <p:grpSpPr>...<a:solidFill><a:schemeClr val="bg1"/></a:solidFill></p:grpSpPr>
    <p:sp><p:cNvPr id="17" name="Freeform 12"/>...<a:custGeom>...</a:custGeom><a:grpFill/>...
  ```
- Why the candidate is wrong: `<a:grpFill/>` is an explicit instruction to use the immediate parent group's `<a:solidFill>` as the shape's fill. Both parent groups declare one (`99CC31` and `bg1`/white respectively); the candidate leaves the shapes unfilled instead of inheriting it.

### 3. Style `fontRef` scheme color not applied to un-styled runs

- Where: every panel heading whose run has no explicit `<a:rPr><a:solidFill>` — "Audit" (id 5), "Panel C" (id 7), "Panel A" (id 14), "Panel B" (id 15), "Detect" (id 28), "Product X" (id 38), "ThreatScore" (id 36, partially off the visible frame).
- Reference: white text on every one of these (dark text only appears where the run has an explicit `<a:solidFill><a:schemeClr val="tx1"/></a:solidFill>`, e.g. "Control & Analyze").
- Candidate: all of the above render in a flat dark gray, indistinguishable from each other and from the "Control & Analyze"-style dark text.
- XML:
  ```
  <p:style><a:fontRef idx="minor"><a:schemeClr val="lt1"/></a:fontRef></p:style>
  <p:txBody>...<a:rPr lang="en-IN" sz="1600" b="1" dirty="0"/><a:t>Detect</a:t>...
  ```
- Why the candidate is wrong: per the shape style matrix, a run without its own fill takes color from `p:style/a:fontRef`'s scheme color (`lt1`, i.e. white/`bg1` through the master `clrMap`). The candidate appears to fall back to a hardcoded default gray instead of resolving `fontRef`.

### 4. Picture crop (`a:srcRect`) and luminance recolor (`a:lum`) not applied

- Where: "Audit" icon (Picture 5, id 6, `image36.png`, region `[0.091, 0.643, 0.153, 0.763]`), "Panel C" icon (Picture 23, id 24, `image28.png`, region `[0.243, 0.65, 0.305, 0.758]`), "Detect" icon (Picture 28, id 29, `image43.png`, region `[0.693, 0.636, 0.763, 0.757]`).
- Reference: each shows only the small cropped icon glyph — for "Audit" a circular part-green/part-white icon, for "Panel C" a white starburst, for "Detect" a white circular badge — with none of the source artwork's title/subtitle text visible.
- Candidate: each shows the entire source image scaled into the small frame. For "Audit" this is a miniature copy of the whole marketing panel (title "Audit", subtitle "Panel B caption", full icon). For "Panel C" it is the full gray "Panel C" logo lockup (icon + wordmark), not recolored to white. For "Detect" the source panel's "Detect" title and subtitle appear as a faint ghost behind the visible icon.
- XML:
  ```
  Picture 5:  <a:blip r:embed="rId2".../><a:srcRect l="17102" t="25801"/>
  Picture 23: <a:blip r:embed="rId3"><a:lum bright="70000" contrast="-70000"/></a:blip>
              <a:srcRect l="8635" t="33316" r="66843" b="24890"/>
  Picture 28: <a:blip r:embed="rId4".../><a:srcRect t="27763"/>
  ```
- Why the candidate is wrong: `a:srcRect` defines the fraction of the source image to keep before stretching into the shape's frame, and `a:lum` applies a brightness/contrast recolor to the sampled pixels. The source images are shared marketing-panel graphics that only make sense once cropped down to their icon corner; skipping the crop (and, for Picture 23, the recolor) exposes the rest of the artwork verbatim.
