## Reference vs candidate

Slide 7, "Dependencies", shows a title, two section headers ("US Subsidiary", "Worldwide"), two 7-row/7-column-ish DrawingML tables (`Program (US)` and `Program (Global)`) with a dark navy header row and bulleted body text, and a bottom definitions box for L100/L200/SME. LibreOffice draws both tables fully populated with header fills, borders, and text. BetterOffice draws only the tables' bounding rectangle as a dashed outline containing a small "Table" caption — none of the actual rows, cell fills, borders, or text are drawn. The bottom definitions rectangle renders correctly in BetterOffice except that its three bold run prefixes ("L100 – ", "L200 – ", "SME – ") come out unbold.

## Findings

### 1. Both slide tables render as an empty placeholder instead of their content

- Where: `graphicFrame` "Table 4" (id 5, region `[0.029, 0.149, 0.971, 0.536]`) and `graphicFrame` "Table 6" (id 7, region `[0.029, 0.614, 0.97, 0.814]`)
- Reference: LibreOffice draws each table's full grid — a dark navy `firstRow` header band with white bold text ("Program (US)", "Gretchen O'Hara", "David Smith & Casey McGee (Build)", etc.), banded body rows with bulleted text, and thin cell borders throughout.
- Candidate: BetterOffice draws only a light dashed rectangle matching the graphicFrame's bounding box, with the word "Table" centered inside it in gray — no grid lines, no header fill, no cell text at all.
- XML: `<a:graphicData uri="http://schemas.openxmlformats.org/drawingml/2006/table"><a:tbl><a:tblPr firstRow="1" bandRow="1"><a:tableStyleId>{5C22544A-7EE6-4342-B048-85BDC9FD1C3A}</a:tableStyleId></a:tblPr>...` — both frames contain a well-formed `a:tbl` with grid columns, rows, and cell text runs.
- Why the candidate is wrong: the table is present and fully specified in the XML (7 `gridCol`s, header row flag, table style reference, per-cell text runs); BetterOffice's table renderer is evidently not implemented/wired for this shape and falls back to a generic "Table" placeholder box, dropping all content this accounts for the bulk of the slide's diff (the `r1c1`, `r3c1`, `r3c2`, `r3c3` hot cells all fall inside the two table regions).

### 2. Bold run prefixes in the definitions box lose their weight

- Where: `sp` "Rectangle 5" (id 6, region `[0.029, 0.84, 0.971, 0.933]`)
- Reference: "L100 – ", "L200 – ", and "SME – " render in bold, followed by the regular-weight definition text.
- Candidate: all three prefixes render in the same regular weight as the rest of the line; no visible bold anywhere in the box.
- XML: `<a:rPr lang="en-US" sz="1000" b="1" dirty="0">...<a:t>L100 – </a:t>` (same pattern for the "L200 – " and "SME – " runs, each with `b="1"`).
- Why the candidate is wrong: `b="1"` is set explicitly on the run properties for each prefix run; BetterOffice is not applying the bold flag when rendering these runs even though the following, unbolded run in the same paragraph renders correctly at the same size and font.
