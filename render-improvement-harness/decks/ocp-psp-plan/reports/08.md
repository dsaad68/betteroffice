## Reference vs candidate

The slide ("Connections/Integration of Work Across") is a 4-column, 10-row table (Program / Degree of Connection (H/M/L) / Which Team does your work connect/plug into / How/ details) listing rows for Cloud Ready, P-Seller, and MPN programs. The reference (LibreOffice) draws the full table: a dark-blue header row with white text, thin grid lines, and all cell text across the ten rows. The candidate (BetterOffice) draws the title correctly but shows nothing for the table area except a dashed bounding-box outline with the literal placeholder word "Table" centered inside it — no grid, no fills, no cell text.

## Findings

### 1. Table graphicFrame not rendered at all

- Where: `Table 1` (id 2), a `p:graphicFrame` at slide fraction `[0.028, 0.111, 0.98, 0.581]`, essentially the entire content area below the title.
- Reference: Renders the full table — 4 columns × 10 rows, dark navy header row with white bold text ("Program", "Degree of Connection (H/M/L)", "Which Team does your work connect/plug into", "How/ details"), thin borders, and all cell text for the Cloud Ready, P-Seller, and MPN program rows.
- Candidate: Renders only a dashed placeholder rectangle matching the frame's bounding box, with the literal text "Table" drawn in its center — an unimplemented-element stand-in, not the table's actual content, style, or geometry.
- XML: `slide.xml` contains a well-formed table definition on this `graphicFrame`:
  ```xml
  <p:graphicFrame>
    <p:nvGraphicFramePr><p:cNvPr id="2" name="Table 1"/>...</p:nvGraphicFramePr>
    <p:xfrm><a:off x="335280" y="760217"/><a:ext cx="11614040" cy="3223260"/></p:xfrm>
    <a:graphic>
      <a:graphicData uri="http://schemas.openxmlformats.org/drawingml/2006/table">
        <a:tbl>
          <a:tblPr firstRow="1" bandRow="1"><a:tableStyleId>...</a:tableStyleId></a:tblPr>
          <a:tblGrid>
            <a:gridCol w="1656080"/><a:gridCol w="955040"/>
            <!-- two more gridCol entries -->
          </a:tblGrid>
          <a:tr h="397174">...</a:tr>
          <!-- nine more a:tr rows with a:tc cells and text runs -->
        </a:tbl>
      </a:graphicData>
    </a:graphic>
  </p:graphicFrame>
  ```
  A standard OOXML table graphic frame with `tblGrid`, a referenced table style, `firstRow`/`bandRow` banding flags, and fully populated rows/cells — nothing malformed or exotic.
- Why the candidate is wrong: The `a:tbl` graphic type inside `p:graphicFrame` is a normal, fully-specified PowerPoint table. BetterOffice falls back to an "unsupported shape" placeholder (bounding box + type name) instead of laying out and drawing the table; no error appears in `bo-log.json` for slide 08 (`skipped_images: 0`), so the fallback is silent. This single root cause explains essentially the whole `fine_pct` diff and all four hot cells (r1c1–r1c4), since the reference has real content across the whole grid and the candidate is blank there. Same failure mode as slide 4 of this deck.
