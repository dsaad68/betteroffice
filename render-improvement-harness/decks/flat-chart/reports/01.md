## Reference vs candidate

The slide is a title/body layout with a triangle bar chart on the right. LibreOffice renders "ENTER TITLE HERE" with wide, evenly tracked letters that overflow the title box width and wrap to two lines ("ENTER TITLE" / "HERE"), and it wraps the two Lorem Ipsum paragraphs into 5 lines each. BetterOffice renders the same title and body text with tight, un-tracked kerning: the title fits on a single line, and each paragraph packs into 3-4 lines instead of 5. The chart itself (triangles, callouts, year labels) matches closely between the two renders.

## Findings

### 1. Character spacing (`spc`) not applied, changing line wrap in title and body text

- Where: TextBox 39 "ENTER TITLE HERE" (id 40, region ~[0.012, 0.023, 0.482, 0.126]); TextBox 36 "CREATIVE VENUS" (id 37, region ~[0.015, 0.18, 0.32, 0.247]); Rectangle 38 body copy (id 39, region ~[0.018, 0.26, 0.311, 0.51])
- Reference: LibreOffice draws every character in these three runs with visible extra spacing between letters (a wide, tracked look). The added width pushes "ENTER TITLE HERE" past the box's 5731079 EMU width, wrapping it to two lines, and pushes each Lorem Ipsum paragraph to 5 wrapped lines.
- Candidate: BetterOffice draws the same text with normal/tight kerning, no visible extra letter spacing. The narrower text fits "ENTER TITLE HERE" on one line, and each paragraph wraps into fewer, wider lines (4 then 3, versus 5 then 5 in the reference).
- XML: all three runs carry the same run property:
  ```xml
  <a:rPr lang="en-IN" sz="4000" spc="300" ...>  <!-- id 40, "ENTER TITLE HERE" -->
  <a:rPr lang="en-IN" sz="2400" spc="300" ...>  <!-- id 37, "CREATIVE VENUS" -->
  <a:rPr lang="en-IN" sz="1050" spc="300" ...>  <!-- id 39, body paragraphs -->
  ```
- Why the candidate is wrong: `spc` is a valid OOXML run property giving extra inter-character spacing in hundredths of a point (300 = +3pt per character). It is explicitly set on every run in this text block, and LibreOffice visibly honors it (the tracked, wide letterforms). BetterOffice appears to ignore `spc` entirely, so text measures narrower than it should, which changes not just the letterform spacing but the line-break decisions for both the title and the body paragraphs.
