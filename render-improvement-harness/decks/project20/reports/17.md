## Reference vs candidate

This is the closing "thank you" slide: a logo box on the left, a large "THANK YOU" headline and email address in the middle, and a website URL centered at the bottom. LibreOffice draws "THANK YOU" as huge (~80pt) bold text, centered in its box, wrapping to two lines ("THANK" / "YOU") and overlapping the email line below it. BetterOffice draws the same text far smaller, unbolded, left-aligned, fitting on a single line with no overlap. The logo, email text, and URL text match between renders (position/content), aside from anti-aliasing.

## Findings

### 1. "THANK YOU" placeholder uses master body style instead of the layout's placeholder-specific style

- Where: "Text Placeholder 1" (id 2), region `[0.357, 0.422, 0.937, 0.6]`
- Reference: 80pt bold text, centered horizontally in the box, no bullet, wrapping to two lines and visually dominating the slide.
- Candidate: roughly 38-40pt regular-weight text, left-aligned near the box's left edge, single line, much smaller footprint.
- XML: the slide shape has no local overrides at all —

```xml
<p:sp><p:nvSpPr><p:cNvPr id="2" name="Text Placeholder 1"/>
  <p:nvPr><p:ph type="body" sz="quarter" idx="10"/></p:nvPr></p:nvSpPr>
<p:spPr/>
<p:txBody><a:bodyPr/><a:lstStyle/>
  <a:p><a:r><a:rPr lang="en-IN"/><a:t>THANK YOU</a:t></a:r></a:p>
</p:txBody></p:sp>
```

  The layout defines a placeholder with the exact matching `type="body" sz="quarter" idx="10"` and a placeholder-level `lstStyle` that should win over the master's generic body style:

```xml
<p:sp><p:nvPr><p:ph type="body" sz="quarter" idx="10" hasCustomPrompt="1"/></p:nvPr>
  <p:spPr><a:xfrm><a:off x="4357393" y="2891722"/><a:ext cx="7060883" cy="1225965"/></a:xfrm></p:spPr>
  <p:txBody><a:bodyPr/>
    <a:lstStyle><a:lvl1pPr marL="0" indent="0" algn="ctr"><a:buNone/>
      <a:defRPr sz="8000" b="1"><a:solidFill><a:schemeClr val="tx1"/></a:solidFill>
        <a:latin typeface="+mn-lt"/></a:defRPr>
    </a:lvl1pPr></a:lstStyle>
  ...
```

  The master's `bodyStyle` (which the candidate appears to be using instead) has an unrelated, much smaller default:

```xml
<p:bodyStyle><a:lvl1pPr marL="336145" indent="-336145" algn="l" ...>
  <a:defRPr sz="3921" .../>
```

- Why the candidate is wrong: the box position (x0/y0 ≈ 0.357/0.422) is correctly inherited from the layout's `xfrm`, so shape geometry resolution works. But the text run has no local `sz`/`b`/`algn` and no local `lstStyle`, so per OOXML inheritance it must take character and paragraph properties from the *placeholder-matching* shape's `lstStyle` in the layout (`sz="8000" b="1" algn="ctr"`, no bullet) — not from the master's generic `bodyStyle` (`sz="3921"`, left-aligned, bulleted margins). The candidate's font size (~38-40pt measured), lack of bold, and left-start position (offset from the box's left edge by roughly the master's `marL="336145"` bullet indent) all match the master default being used in place of the layout's placeholder-specific style.
