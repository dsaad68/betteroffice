## Reference vs candidate

Slide 8 is a section-divider slide: a navy square (from the layout) with a thin inset border, a white document/checklist icon centered in it, and a large bold navy "CONVERSATION GUIDES" title to its right that wraps to two lines. The layout-drawn navy square and border render identically in both engines. LibreOffice fills in the white icon and renders the title in large bold navy text wrapped as "CONVERSATI" / "ON GUIDES". BetterOffice leaves the icon area blank (just the plain navy square) and renders the title as small, unbold, gray text on a single line, positioned differently within its box.

## Findings

### 1. Icon shapes with `a:grpFill` render with no fill, making the icon invisible

- Where: `Group 3` (id 4, slide), containing `Rectangle 83` (id 6, the document/pie-chart custGeom icon path) and `Rectangle 6` (id 7, a thin strip above it, part of the icon's top tab). Region [0.118, 0.386, 0.215, 0.614].
- Reference: LibreOffice draws both shapes filled white (`bg1`), producing the visible checklist/document icon against the navy background.
- Candidate: BetterOffice draws neither shape's fill — the icon is entirely absent, leaving only the plain navy square with its border.
- XML:
  ```xml
  <p:grpSp>
    <p:grpSpPr>...<a:solidFill><a:schemeClr val="bg1"/></a:solidFill></p:grpSpPr>
    <p:sp><!-- Rectangle 83, id 6 -->
      <p:spPr><a:custGeom>...</a:custGeom><a:grpFill/><a:ln><a:noFill/></a:ln></p:spPr>
    </p:sp>
    <p:sp><!-- Rectangle 6, id 7 -->
      <p:spPr><a:prstGeom prst="rect"/><a:grpFill/><a:ln><a:noFill/></a:ln></p:spPr>
    </p:sp>
  </p:grpSp>
  ```
- Why the candidate is wrong: both child shapes declare `<a:grpFill/>` with no other fill, meaning they must take their fill from the enclosing group's `<a:solidFill><a:schemeClr val="bg1"/></a:solidFill>`. BetterOffice paints them as unfilled/transparent instead, so the icon never appears.

### 2. Title placeholder text uses master default style instead of the layout's placeholder-specific style

- Where: `Text Placeholder 4` (id 5, slide, `ph type="body" sz="quarter" idx="10"`), box inherited from the layout's placeholder idx 10: off (4884058, 3065150) ext (6674464, 727700) EMU → frac [0.401, 0.447, 0.947, 0.553].
- Reference: LibreOffice renders "CONVERSATION GUIDES" bold, navy (`24265D`), at a size large enough (layout specifies 66pt) that it wraps to two lines within the placeholder's width: "CONVERSATI" / "ON GUIDES".
- Candidate: BetterOffice renders the same text unbold, in gray, at a visibly smaller size that fits entirely on one line — consistent with falling back to the slide master's generic `bodyStyle` `lvl1pPr` (`sz="3921"`, `schemeClr val="tx1"`, `latin typeface="+mj-lt"`) rather than the layout's own placeholder `lstStyle` override.
- XML:
  ```xml
  <!-- layout, placeholder idx=10 -->
  <a:lstStyle><a:lvl1pPr marL="0" indent="0" algn="l">
    <a:defRPr sz="6600" b="1">
      <a:solidFill><a:srgbClr val="24265D"/></a:solidFill>
      <a:latin typeface="+mn-lt"/>
    </a:defRPr>
  </a:lvl1pPr></a:lstStyle>
  <!-- master bodyStyle, what the candidate appears to use instead -->
  <a:lvl1pPr><a:defRPr sz="3921" ...><a:solidFill><a:schemeClr val="tx1"/></a:solidFill><a:latin typeface="+mj-lt"/></a:defRPr></a:lvl1pPr>
  ```
- Why the candidate is wrong: the slide's `<p:sp>` for this placeholder has an empty `<p:spPr/>` and a run with no `rPr` overrides, so all paragraph/run formatting must come from inheritance. The layout's own placeholder shape for the same `idx="10"` carries an explicit `lstStyle` with `sz="6600"`, `b="1"`, and a navy `solidFill` — this placeholder-level list style takes precedence over the master's generic `bodyStyle`. BetterOffice's output (smaller, unbold, gray, major-font) matches the master default almost exactly, indicating the layout placeholder's `lstStyle` override is being skipped during inheritance resolution.
