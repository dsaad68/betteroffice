## Reference vs candidate

The slide is a "Partner Questionnaire" content slide: a navy title bar, a blue "Resources" side panel, and a light-gray content box holding a four-item numbered list ("Website", "Sources of additional info", "links to documents available to partner sellers", "List of success stories/case studies available to sellers"). Layout, colors, box positions, and the checklist icon all match between renderers. Two things differ: the title and "Resources" labels are bold in the reference but regular weight in the candidate, and the reference numbers the four list items 1–4 while the candidate drops the numbers entirely (leaving the hanging-indent gap where they should be).

## Findings

### 1. Bold runs rendered at regular weight

- Where: "Rectangle 2" (id 3), the "Partner Questionnaire" title in the navy bar, region ≈ [0.022, 0.053, 0.979, 0.139]; and "Rectangle 5" (id 6), the "Resources" label in the blue panel, region ≈ [0.0, 0.175, 0.227, 0.982].
- Reference: both strings are drawn in a heavy/bold weight (thick strokes on "Partner Questionnaire" and "Resources").
- Candidate: both strings are drawn in a thin, regular weight — same typeface and size, but no bold applied.
- XML: title run —
  ```xml
  <a:rPr lang="en-US" sz="3600" b="1" spc="-100">...</a:rPr><a:t>Partner Questionnaire </a:t>
  ```
  "Resources" run —
  ```xml
  <a:rPr lang="en-US" sz="2800" b="1"><a:solidFill>...</a:solidFill>...</a:rPr><a:t>Resources</a:t>
  ```
- Why the candidate is wrong: both runs explicitly set `b="1"` with no overriding `b="0"` anywhere in scope; the reference honors it, the candidate does not.

### 2. List auto-numbering not drawn

- Where: "Rectangle 7" (id 8), the four-line list in the content box, region ≈ [0.253, 0.187, 0.979, 0.966].
- Reference: each paragraph is prefixed with an Arabic-period number, "1." through "4.", left of the hanging-indented text.
- Candidate: no number glyph is drawn for any paragraph; the text itself still starts at the same hanging-indent x-position (measured start x=388px vs the reference's number start x=337px and matching text start x=388px), i.e. the indent geometry came through but the bullet content did not.
- XML: each paragraph —
  ```xml
  <a:pPr marL="514350" indent="-514350" fontAlgn="ctr">
    <a:buFont typeface="+mj-lt"/><a:buAutoNum type="arabicPeriod"/>
  </a:pPr>
  ```
- Why the candidate is wrong: `<a:buAutoNum type="arabicPeriod"/>` requests automatic "1.", "2.", … numbering using the major-latin theme font; the candidate applies the paragraph's `marL`/`indent` hanging geometry but never renders the numbering glyph itself.

## Not reported

- Minor anti-aliasing differences on the checklist icon and panel borders.
