## Reference vs candidate

A single-title slide: "Why we think Elixir is Uniquely positioned to serve you" in gold text on the deck's dark purple background, with the Elixir logo bottom-right. LibreOffice draws the title at its specified 48pt, wrapped across five lines in a monospaced fallback font, with the placeholder box grown taller (via `spAutoFit`) around its vertical center to fit all five lines. BetterOffice draws the same text in a proportional sans-serif fallback but at a visibly smaller size, wrapping to only two lines that fit inside the placeholder's original, un-grown height.

## Findings

### 1. Title font size shrunk instead of growing the placeholder (`spAutoFit` mishandled)

- Where: "Title 3" (id 4), region ≈ [0.208, 0.272, 0.821, 0.45] (the placeholder's slide.xml box before any autofit growth)
- Reference: the "W" cap-height measures 48px; consistent with the run's explicit `sz="4800"` (48pt) rendering at full size. At that size the text wraps to five lines, so LibreOffice grows the shape's height from the box's 128px (`cy="1218795"`) up to roughly 308px, expanding symmetrically around the box's vertical center (consistent with `anchor="ctr"`).
- Candidate: the same "W" measures 31px cap-height — about 65% of the reference's size, i.e. an effective ~31pt instead of the specified 48pt. Because the font is smaller, the same box width fits far more text per line, so the title wraps to only two lines and the box is left at its original, un-grown 128px height.
- XML:
  ```xml
  <p:spPr><a:xfrm><a:off x="2057401" y="1867123"/><a:ext cx="6063761" cy="1218795"/></a:xfrm>...</p:spPr>
  <p:txBody>
    <a:bodyPr wrap="square" lIns="0" tIns="0" rIns="0" bIns="0" anchor="ctr">
      <a:spAutoFit/>
    </a:bodyPr>
    <a:lstStyle/>
    <a:p>...
      <a:r><a:rPr lang="en-US" sz="4800" dirty="0">
        <a:solidFill><a:srgbClr val="C19859"/></a:solidFill>
        <a:latin typeface="Sakkal Majalla"/>
      </a:rPr><a:t>Why we think Elixir is Uniquely positioned to serve you </a:t></a:r>
    </a:p>
  </p:txBody>
  ```
- Why the candidate is wrong: `<a:spAutoFit/>` ("shape autofit") means the shape resizes to fit the text at its specified size — it never shrinks the font. Font-size shrinking on overflow is what `<a:normAutofit>` (with a `fontScale`) would request, and that element is absent here. Since the run's `sz="4800"` is explicit (not inherited), BetterOffice has no basis for reducing it; the placeholder box should have grown taller instead, as LibreOffice's render shows.
