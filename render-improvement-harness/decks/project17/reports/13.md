### 2. Non-first run in a paragraph loses its explicit run color

- Where: five text boxes, each a single paragraph with 2-4 runs where a middle or later run carries `<a:solidFill><a:srgbClr val="A99A72"/></a:solidFill>` (a tan/gold emphasis color) while the first run is black (`000000`):
  - TextBox 54 ("Over 300 PMO engagements in last three years") — run 2 of 3, `300 PMO engagements `
  - TextBox 55 ("More than 120 consultants...") — runs 2, 4, 5 of 5, `120 consultants `, `PMO`, ` experience`
  - TextBox 56 ("More than 90 consultants...") — runs 2 and 4 of 4, `90 consultants `, `communication in change situations `
  - TextBox 58 ("Significant knowledge on best practices...") — run 2 of 4, `best practices `
  - TextBox 59 ("Integrative capability across content and process") — run 2 of 2, `content and process`
- Reference: each listed phrase renders in the gold/tan `A99A72` accent color, the rest of the sentence in black, matching the run-level `solidFill` in the XML.
- Candidate: every one of these phrases renders in plain black — indistinguishable from the surrounding text. By contrast, TextBox 57 ("Proprietary program management toolkit and templates"), whose gold-colored run happens to be the *first* run in its paragraph, renders correctly gold in both engines.
- XML (TextBox 55, runs 1-2):
  ```xml
  <a:r><a:rPr .../><a:solidFill><a:srgbClr val="000000"/></a:solidFill>...<a:t>More than </a:t></a:r>
  <a:r><a:rPr .../><a:solidFill><a:srgbClr val="A99A72"/></a:solidFill>...<a:t>120 consultants </a:t></a:r>
  ```
- Why the candidate is wrong: each run's `<a:rPr><a:solidFill>` is explicit and unambiguous — there is no inheritance question here, every run in every affected paragraph directly specifies its own color. The pattern (correct only when the colored run is first) points to BetterOffice applying the first run's resolved color/style to the rest of the paragraph's runs instead of resolving each run's own `rPr` independently.
